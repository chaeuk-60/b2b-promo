# E2E 테스트 리포트 (Playwright MCP 기반 수동 주행 테스트)

- **테스트 방식**: Playwright MCP(chrome-devtools MCP)로 실제 개발 서버(frontend `http://localhost:5173`, backend `http://localhost:3000`)를 브라우저로 직접 조작하며 검증. 자동 회귀 테스트 스위트가 아니라, `docs/5-user-scenarios.md`의 5개 시나리오와 화면별 유스케이스를 근거로 한 1회성 탐색적 E2E 주행 기록이다.
- **테스트 일시**: 2026-08-21
- **대상 커밋**: `ed1fe4c` (Y2K 픽셀 배경 그라데이션 + 팝업/말풍선 레퍼런스 반영) 시점
- **DB**: 로컬 PostgreSQL(`postgresql://postgres@localhost:5432/postgres`), 시드 데이터(`backend/src/db/seed.sql`) + 기존 테스트 계정 그대로 사용. 이번 테스트를 위해 신규 계정 2개(`e2e-newbie@example.com`, `e2e-tombstone@example.com`)를 생성했고, 후자는 사망(묘비) 시나리오 재현을 위해 `pets.last_active_at`을 DB에서 직접 8일 전으로 되돌렸다(정상 사용자 흐름으로는 재현에 며칠이 걸리므로 시간 경과만 모사).
- **스크린샷**: `e2e/screenshots/` (주요 화면 15장 `NN-*.png`, 예외/엣지 케이스 10장 `edge-NN-*.png`, 총 25장)

## 3. 발견된 결함

### 3.1 회원가입 실패 시, 로그인 폼의 이전 에러 메시지가 남아 잘못된 안내를 띄움 (재현 확실)

- **위치**: `frontend/src/pages/LoginPage.jsx`의 `errorMessage` 계산 로직
- **재현 절차**:
  1. 로그인 폼에서 잘못된 비밀번호로 로그인 시도 → "이메일 또는 비밀번호가 올바르지 않습니다." 노출(정상)
  2. "회원가입" 모드로 전환 후, 이미 가입된 이메일로 회원가입 시도
- **기대 동작**: 백엔드가 내려주는 회원가입 전용 에러(`EMAIL_TAKEN`, "이미 가입된 이메일입니다.")가 표시되어야 함
- **실제 동작**: 네트워크 탭에서는 `POST /auth/signup → 400 {"error":{"code":"EMAIL_TAKEN","message":"이미 가입된 이메일입니다."}}`가 정확히 내려오지만, 화면에는 1단계에서 남아있던 로그인 에러 문구가 그대로 표시됨(`edge-02` 스크린샷)
- **원인**: `errorMessage`가 `loginMutation.isError`를 `signupMutation.isError`보다 무조건 먼저 확인하며, 두 `useMutation` 상태 모두 모드 전환 시 리셋되지 않아 이전 실패 상태가 계속 남아있음
- **제안 수정**: 모드(`mode`)가 바뀔 때 `loginMutation.reset()`/`signupMutation.reset()` 호출, 그리고 `errorMessage`를 "현재 `mode`에 해당하는 mutation의 에러만" 보도록 수정

### 3.2 관리자 계정도 페이지를 새로고침하면(또는 URL 직접 이동) 관리자 페이지에 접근할 수 없음 (재현 확실, 심각도 높음)

- **위치**: `frontend/src/store/auth.store.js`(영속화 없음) + `frontend/src/pages/AdminPromotionsPage.jsx`(`user` 스토어 값에만 의존한 판별)
- **재현 절차**:
  1. `admin@b2b-promo.com` / `admin1234!`로 정상 로그인(로그인 성공, 세션 쿠키·액세스 토큰 정상 발급 확인)
  2. 주소창에 `http://localhost:5173/admin/promotions` 직접 입력(또는 새로고침) 후 이동
- **기대 동작**: 관리자 페이지(프로모션 등록/수정 폼)가 노출되어야 함
- **실제 동작**: `/promotions`로 즉시 리다이렉트됨(`edge-06` 스크린샷). 실제로는 백엔드 인증은 여전히 유효한 상태(같은 계정으로 `/promotions`, `/pet` 등 다른 API 호출은 정상 동작)
- **원인**: 로그인 사용자 정보(`useAuthStore.user`)가 Zustand 메모리에만 저장되고 새로고침/전체 페이지 이동 시 초기화됨. 앱 어디에도 마운트 시 "내 정보 조회"로 `user`를 복원하는 로직이 없음. 게다가 네비게이션 어디에도 관리자 페이지로 가는 인앱(클라이언트 라우팅) 링크가 없어, 실사용자가 이 페이지에 도달하는 유일한 방법은 주소창에 URL을 직접 입력하는 것뿐인데 이 방법 자체가 항상 전체 페이지 로드(=상태 초기화)를 유발함
- **영향**: 이 버그가 존재하는 한, 관리자는 **정상적인 브라우저 사용 방식으로는 관리자 페이지에 절대 도달할 수 없음**(로그인 폼 제출 직후 같은 탭에서 클라이언트 라우팅으로 이동할 방법이 없기 때문)
- **제안 수정**: 앱 최상단(`main.jsx`/`App.jsx`)에서 마운트 시 액세스 토큰 재발급(`/auth/refresh`)이 성공하면 `/auth/me` 또는 `login` 응답과 동일한 사용자 정보를 조회해 `useAuthStore.setUser`로 복원하는 로직 추가. 최소한 관리자 이메일 배지 등 관리자용 네비게이션 링크를 노출해 인앱 이동 경로도 확보할 것

### 3.3 (경미) 기간 종료 프로모션은 목록에서 상세로 갈 방법이 없음

- 목록 화면(`PromotionCard`)은 기간 종료 시 "기간 종료" 비활성 버튼만 노출하고 상세로 가는 링크를 렌더링하지 않음. 상세 페이지(`/promotions/:id`) 자체는 기간 종료 상태를 정상 처리하지만, 목록에서 그 카드를 클릭해 도달할 수 있는 경로가 없어(제목도 링크가 아님) 실사용자는 URL을 몰라 상세 화면의 "담당자에게 연락 주세요" 안내조차 보기 어려움. 기능 결함은 아니지만 UX 개선 여지로 기록.

## 4. 테스트 환경 한계 (참고용, 결함 아님)

- **13/14번 스크린샷(오늘의 운세/쓰다듬기 반응)**: 반응 말풍선은 4초간만 노출되는데(`PetPanel.jsx` `REACTION_DURATION_MS`), 이 세션의 Playwright MCP(chrome-devtools) 도구 자체의 호출 왕복 지연(스크린샷 1건에 최대 120초까지 걸린 사례 있음)이 이 4초보다 커서, 클릭 직후 접근성 스냅샷(a11y tree)에서는 반응 문구(`🍀 꾸준함이 빛을 발하는 하루가 될 거예요.` 등)가 정상적으로 잡혔지만, 뒤이은 스크린샷 촬영 시점엔 이미 사라진 뒤였다. 기능 자체는 네트워크 응답과 DOM 스냅샷으로 정상 동작을 확인했다(10번 특식 급여 반응은 타이밍이 맞아 정상 캡처됨).
- **반응형 브레이크포인트(480px) 검증**: `mcp__chrome-devtools__resize_page`가 이 환경에서 501px 미만으로는 축소되지 않는 하한이 있어(`emulate` 도구의 `viewport` 옵션으로 우회), 실제 앱 버그가 아님을 확인 후 진행함.

## 5. 도메인 시나리오 커버리지 (`docs/5-user-scenarios.md`)

| 시나리오 | 커버리지 |
|---|---|
| 1. 신규 가입자의 첫 사용 | ✅ 재현(회원가입 → 알 생성 → 목욕/밥으로 activityCount 누적) |
| 2. 특식 요청 → 신청 유도 | ✅ 재현(신규 펫이 로그인 직후 "특식 요청" 상태로 시작, 보유 특식 급여까지 진행) |
| 3. 미접속 → 사망(묘비) | ✅ 재현(DB로 `last_active_at`을 8일 전으로 되돌려 시간 경과를 모사, 재로그인 시 묘비 전환 + 다음 로그인에 새 알 교체까지 확인) |
| 4. 자발적 급여(진화/반짝이 50:50) | ▲ 부분 재현 — 특식 요청 상태에서 요청 대상이 아닌 특식을 급여했더니 "진화(activityCount+1)" 분기가 나옴(확률적 동작이라 매 실행 다른 결과가 나올 수 있음, 버그 아님) |
| 5. 성체 순환/선물 지급(2주 경과) | ⏭ 미실행 — 실시간 2주 경과가 필요해 이번 탐색적 테스트 범위에서 제외(추후 DB 시간 조작으로 재현 가능) |
