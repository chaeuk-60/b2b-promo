## 시나리오 1. 신규 가입자의 첫 사용
**참고**: 도메인 정의서 §1(개요), §3 펫 엔티티, §5.1(성장 단계 전이), §6(비즈니스 규칙); PRD 5.1절

- **상황**: 거래처 담당자가 앱을 처음 알게 되어 가입한다.
- **단계별 행동**:
  1. 이메일/비밀번호로 회원가입 (§3 사용자 엔티티)
  2. 가입과 동시에 펫 1마리가 자동 생성됨. stage=알, eggState=평범, activityCount=0 (§6, PRD 5.1)
  3. 로그인 시 lastActiveAt 갱신, 접속 횟수 카운트 시작 (§5.1 사망 판정 기준, PRD 5.1)
  4. 프로모션 목록을 둘러보다가 관심 가는 프로모션 하나를 "찜"만 해둔다 (§4 관계, §6 찜 토글)
  5. 펫 화면에서 알을 목욕/밥 주기로 돌본다. activityCount가 쌓인다 (§5.1 단계별 행동표)
- **결과**: activityCount가 2회 이상 누적되면 50% 확률로 부화 판정이 시작되고, 성공 시 새끼로 성장하며 귀 모양이 랜덤으로 고정된다 (§5.1 성장 단계 전이, §6 귀 모양 규칙). 아직 신청은 하지 않은 상태.

## 시나리오 2. 찜만 하고 신청은 안 한 사용자가 펫의 "특식 요청"을 받는 흐름
**참고**: 도메인 정의서 §5.1(특식 요청 대상 선정, 찜만 한 프로모션 70% 가중치), §9(문제#1 대응 규칙)

- **상황**: 사용자가 프로모션 A를 찜만 해두고 신청은 하지 않은 채 며칠간 접속한다.
- **단계별 행동**:
  1. 로그인할 때마다 mood(또는 eggState)가 랜덤으로 재설정됨 (§5.1 기분 전이, §2 용어 정의)
  2. 어느 날 로그인 시 mood가 "특식 요청"으로 뽑힘. requestedPromotionId 선정 로직이 동작: 찜만 하고 신청 안 한 프로모션(A)이 있으므로 70% 확률로 A가 선정됨 ("특식 줘") (§5.1 특식 요청 대상 선정)
  3. 사용자는 특식을 급여하려면 프로모션 A에 신청해야 특식을 보유하게 됨을 확인 (§2 용어 정의: 특식은 신청 시 보유)
  4. 프로모션 A의 신청 기간이 아직 유효하므로 신청 진행 (§5.1 특식 요청 대상 선정 조건: 신청 완료/기간 종료 프로모션은 후보에서 제외)
  5. 신청 완료 후 특식 A를 보유하게 되고, 이를 펫에게 급여
- **결과**: mood가 "특식 요청" → "무지개"로 변화 (§5.1 mood 전이, §6). 사용자는 특식 요청을 계기로 신청까지 완료 — 문제#1(참여율 저조) 대응 규칙이 의도대로 동작한 흐름 (§9 요구사항 추적 매트릭스).

## 시나리오 3. 며칠간 접속하지 않아 펫이 죽는 흐름
**참고**: 도메인 정의서 §5.1(사망 판정), §7(예외 상황)

- **상황**: 사용자가 새끼 또는 성체 단계의 펫을 키우던 중 바빠서 앱을 오래 열지 않는다.
- **단계별 행동**:
  1. 마지막 로그인 이후 lastActiveAt이 갱신되지 않은 채 시간이 흐름 (§3 펫 엔티티 lastActiveAt)
  2. 7일 이상 미접속 상태가 됨 (§5.1 사망)
  3. (다른 전이 조건, 예: 성체 순환 2주 경과가 동시에 해당되더라도 사망 조건이 우선 적용됨) (§5.1 성체 순환, §5.1 사망)
  4. 이후 사용자가 오랜만에 앱에 접속(로그인)함
- **결과**: 로그인 시점에 펫 stage가 "묘비"로 전환되어 있고 "자주 오세요..." 메시지가 표시됨 (§5.1 사망, §7 예외 상황). 이 로그인에서 다음 로그인 시 새 알로 교체된다는 안내를 접하거나, 바로 이어지는 로그인에서 activityCount가 초기화된 새 알로 교체됨 (§5.1 사망, §7).

## 시나리오 4. 프로모션 신청 후 특식을 얻어 펫을 키우는 흐름(자발적 급여)
**참고**: 도메인 정의서 §2(자발적 급여 정의), §6(자발적 급여 특수효과), §5.1(단계별 행동)

- **상황**: 사용자가 딱히 "특식 요청"을 받지 않은 상태에서, 마음에 드는 프로모션에 스스로 신청한다.
- **단계별 행동**:
  1. 프로모션 목록/상세에서 신청 가능 기간 내의 프로모션 B를 확인하고 신청 (§7 예외 상황: 기간 내에만 가능, 중복 신청 방지)
  2. 신청 완료 즉시 프로모션 B의 특식을 보유하게 됨 (§2 용어 정의: 특식)
  3. 현재 펫의 mood/eggState가 "특식 요청"이 아닌 상태에서, 사용자가 자발적으로 특식 B를 급여함 (§2 자발적 급여 정의)
- **결과**: 90% 확률로 일반 밥과 동일하게 처리되고(mood "배고픔"이었다면 평범으로), 10% 확률로 특수효과 발생 — 그중 50%는 진화(activityCount +1), 50%는 mood/eggState가 "반짝이"로 변화 (§6 비즈니스 규칙). 이후 계속 목욕/밥/쓰다듬기를 반복하며 activityCount를 쌓아 성체로 성장시킬 수 있음 (§5.1 성장 단계 전이).

## 시나리오 5. 성체 펫의 장기 육성 — 선물(쿠폰) 지급과 성체 순환
**참고**: 도메인 정의서 §5.1(성체 순환), §6(선물 지급 규칙), §9(문제#2 대응)

- **상황**: 사용자가 매일 접속하며 펫을 성체까지 키운 뒤에도 꾸준히 로그인한다.
- **단계별 행동**:
  1. 성체가 된 시점부터 stageChangedAt이 기록됨 (§3 펫 엔티티)
  2. 매일 접속하며 하루 3회 이상 접속을 달성하는 날에는 mood가 "행복"으로 바뀌고 화면에서 돌아다니는 모션을 봄 (§5.1 기분 전이)
  3. 접속할 때마다 성체 단계에서 5% 확률로 선물(할인 쿠폰)이 지급되는지 판정됨. 단, 마지막 지급으로부터 3일 이내면 지급되지 않음 (§6 비즈니스 규칙, §3 lastGiftAt)
  4. 성체가 된 지 2주가 지나도록 사망(7일 미접속) 조건에 걸리지 않고 계속 접속을 유지함
- **결과**: 2주가 지나는 시점에 성체가 새 알 하나를 남기고 사라지며(성체 순환), 이때는 확률과 무관하게 선물(할인 쿠폰)이 100% 지급됨. 사용자는 다시 알부터 육성을 시작하게 됨 (§5.1 성체 순환, §6 비즈니스 규칙). 이 반복 사이클이 재방문(MAU) 유인으로 작동함 (§9 요구사항 추적 매트릭스: 문제#2 대응).
