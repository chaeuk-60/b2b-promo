# 와이어프레임: b2b-promo

## 문서 정보
- 기반 문서: `docs/1-domain-definition.md`, `docs/4-use-case-diagram.md`, `docs/3-PRD.md`, `docs/5-user-scenarios.md`, `docs/7-arch-diagram.md`
- 목적: 화면별 저해상도 레이아웃 정리(시각 디자인 아님). 새 화면/기능 창작 없음, 문서에 정의된 요소만 배치.
- 레이아웃 기준: PRD 5.4절에 따라 데스크톱/모바일용 화면을 따로 만들지 않고, **하나의 마크업이 화면 폭에 따라 재배치되는 반응형 레이아웃**을 기준으로 작성(별도 컴포넌트 분기 없음).

## 반응형 동작 원칙
- **좁은 화면(모바일)**: 요소가 세로 1열로 쌓임. 카드 리스트는 1열, 상단 네비게이션은 아이콘 위주로 축소.
- **넓은 화면(데스크톱)**: 카드 리스트가 여러 열 그리드로 배치되고, 네비게이션 항목이 가로로 나란히 펼쳐짐. 새 정보나 기능은 추가되지 않고 배치만 바뀜.
- 아래 각 화면 와이어프레임은 좁은 화면 기준 1개만 그리되, 목록형 화면(3번)에는 넓은 화면일 때의 배치 차이를 예시로 덧붙임.

## 1. 로그인 / 회원가입

```
+--------------------------------------+
|              b2b-promo                |
|                                        |
|   [ 이메일          ............ ]    |
|   [ 비밀번호        ............ ]    |
|                                        |
|   [   로그인   ]        [ 회원가입 ]  |
+--------------------------------------+
```

- 이메일/비밀번호 입력창 + 로그인/회원가입 버튼(같은 화면에서 폼만 전환하는 정도, 별도 화면 아님). 두 버튼은 한 줄에 두되 위치/라벨은 모드와 무관하게 항상 "로그인"이 왼쪽, "회원가입"이 오른쪽으로 고정된다. 둘 다 클릭 한 번으로 해당 모드로 전환 + 제출까지 같이 처리한다(사용자 확인: "왜 2번씩 눌러야해?" - 모드 전환용 클릭과 제출용 클릭을 분리하지 않음). 현재 모드에 해당하는 쪽만 주요색으로 강조.
- 로그인/회원가입 실패 메시지는 폼 하단이 아니라 로그인 버튼 바로 오른쪽에 인라인으로 표시한다(사용자 확인).
- 회원가입 성공 시 자동 로그인 처리되며(펫 1마리 자동 생성) 로그인 성공 시에는 항상 프로모션 목록(3번)으로 이동한다. 이름이 없는 상태(최초 로그인 등)에서는 펫 팝업(6번)을 처음 열 때 그 안에서 이름을 짓는다(사용자 확인 - 로그인 직후 별도 화면으로 강제 이동시키지 않음).

## 2. 펫 이름 짓기 (펫 팝업을 처음 열 때, PetPanel.jsx)

```
+--------------------------------------+
|         펫에게 이름을 지어주세요       |
|                                        |
|              [ 알 이미지 ]            |
|                                        |
|   [ 이름 입력            ......... ]  |
|                                        |
|     [  건너뛰기  ]   [  확인  ]        |
+--------------------------------------+
```

- 이름 입력창(선택 입력) + 건너뛰기/확인 버튼. 건너뛰면 기본 이름 사용.
- 별도 화면/URL 이동이 아니라, 펫 팝업(6번)을 열었을 때 pet.name이 없으면 평소 펫 화면 대신 이 폼을 보여준다. 이름을 지으면(또는 건너뛰면) 그 자리에서 바로 평소 펫 화면으로 바뀐다.
- 최초 로그인 후 처음 펫 팝업을 열 때, 그리고 사망(묘비→새 알)·성체 순환으로 새 알이 생긴 뒤 처음 펫 팝업을 열 때 노출된다.

## 3. 프로모션 목록

**좁은 화면 (1열)**
```
+--------------------------------------+
| [나의 신청 목록]             ⎡img⎤ |  <- 상단 네비게이션, 펫 보기는 images/ 스프라이트 축소판(테두리)
+--------------------------------------+
| +------------------------------------+
| | 🍖 프로모션 제목 A                  |  <- 제목은 밑줄 대신 형광펜 하이라이트, 카드를 클릭하면 상세로 이동
| | 기간: 2026-08-01 ~ 2026-08-31       |
| | 내용 요약 한두 줄...                |
| |     [ 신청하기 ]     [ ♡ 찜 ]       |  <- 찜은 신청 상태 버튼 오른쪽에 나란히
| +------------------------------------+
| +------------------------------------+
| | 🍰 프로모션 제목 B                  |
| | 기간: 2026-07-01 ~ 2026-08-10       |
| | 내용 요약 한두 줄...                |
| | [ 기간 종료 ]         [ ♥ 찜 ]      |
| |  ※ 담당자에게 연락 주세요           |  <- 작은 글씨 각주(당구장 표시)
| +------------------------------------+
+--------------------------------------+
```

**넓은 화면 (다열 그리드, 같은 요소·같은 데이터)**
```
+----------------------------------------------------------------+
| 나의 신청 목록                                        ⎡img⎤   |  <- 네비게이션 항목이 가로로 펼쳐짐
+----------------------------------------------------------------+
| +----------------------+  +----------------------+  +---------+
| | 🍖 프로모션 제목 A     |  | 🍰 프로모션 제목 B     |  | ...     |
| | 기간: 08-01~08-31      |  | 기간: 07-01~08-10 (종료)| 열이 계속|
| | [신청하기]  [♡ 찜]    |  | [기간 종료] [♥ 찜]     |  이어짐  |
| |                       |  |  ※ 담당자에게 연락 주세요|         |
| +----------------------+  +----------------------+  +---------+
+----------------------------------------------------------------+
```

- 상단 네비게이션의 "펫 보기"는 텍스트 버튼 대신 `images/` 디렉토리의 펫 스프라이트 축소판을 얇은 테두리로 감싼 버튼으로 표시(클릭 시 펫 화면 이동). 네비게이션 항목은 현재 페이지에 해당하는 탭만 강조 색상으로 표시된다.
- 제목 앞에는 해당 프로모션의 특식 이모지를 표시(프로모션 1개당 특식 1개, `specialFoodId`에 관리자가 직접 입력한 이모지 원문 - 별도 매핑/해시 없음). 제목 글자에는 밑줄 대신 옅은 형광펜(하이라이터) 효과를 준다. 제목 자체는 더 이상 링크가 아니며, **카드 전체를 클릭**하면 상세 화면으로 이동한다(사용자 확인: 별도 "상세보기" 버튼 없이 카드 클릭). 목록 카드에는 제목표시줄(색깔 바)을 쓰지 않는다(펫 팝업/상세 화면과 구분).
- 카드형 리스트: 특식 이모지+제목/기간/내용 요약 + 신청 상태 버튼과 찜 토글 버튼(♡/♥)이 한 줄에 나란히(찜이 신청 버튼 오른쪽) 반복. "신청하기"는 카드 클릭(상세 이동)과 분리된 별도 버튼으로, 누르면 상세로 이동하지 않고 그 자리에서 바로 신청된다.
- 찜은 목록에서 즉시 토글, 기간 종료된 프로모션은 신청 버튼이 비활성화되고 "※ 담당자에게 연락 주세요" 각주 문구(본문보다 작은 글씨)가 함께 표시됨.
- 좁은 화면과 넓은 화면은 같은 데이터·같은 요소를 쓰고, CSS 그리드 열 개수만 화면 폭에 따라 바뀐다(컴포넌트/API 분기 없음).

## 4. 프로모션 상세보기

```
+--------------------------------------+
| [ < 목록으로 ]                        |
+--------------------------------------+
|  🍖 프로모션 제목 A                   |  <- 목록과 같은 형광펜 하이라이트, 제목표시줄 없음
|  기간: 2026-08-01 ~ 2026-08-31        |
|                                        |
|  ----------------------------------   |
|  상세 내용(detail_content)             |  <- 목록의 "내용 요약"(content)과 다른 별도 필드
|  (긴 설명 텍스트...)                   |
|  ----------------------------------   |
|                                        |
|     [   신청하기   ]      [ ♡ 찜 ]    |  <- 찜이 신청 버튼 오른쪽에 나란히
|      (신청됨: "신청 완료" 표시로 전환) |
|      ※ 취소는 담당자에게 연락 주세요  |  <- 신청 완료 시에만 작은 각주로 노출
+--------------------------------------+
```

- 제목(형광펜 하이라이트)/기간/상세 내용 + 하단에 신청 상태 버튼과 찜 토글이 나란히(신청 완료 시 상태 표시로 전환, 중복 신청 방지). 나의 신청 목록 카드와 같은 톤(제목표시줄 없는 일반 제목)으로 통일.
- 상세 내용(`detail_content`)은 목록 카드의 "내용 요약"(`content`)과 별도 필드다(사용자 확인: "리스트에 뜨는 내용하고 간단 내용 상세내용 해서"). `detail_content`가 비어있으면 프론트가 `content`로 대체 표시한다. 관리자 등록/수정 화면(와이어프레임 범위 밖, `AdminPromotionsPage.jsx`)에서 두 필드를 각각 입력한다.
- 신청 완료된 프로모션에는 취소 기능이 없으므로 "※ 취소는 담당자에게 연락 주세요" 각주 문구만 표시.

## 6. 펫 화면

```
+--------------------------------------+
| [프로모션 목록]                       |
+--------------------------------------+
|  이름: 몽실이                          |
|  상태: 배고픔                          |
|                                        |
|  ┌──────────(초원 배경)──────────┐   |
|  │   ("꼬르륵... 배고파요")       │   |  <- 말풍선은 펫을 따라다님
|  │        [펫]  (돌아다님)        │   |
|  └────────────────────────────────┘   |
|                                        |
|  [ 목욕 ]     [ 밥 ▼ ]     [ 쓰다듬기 ]  |
|                                        |
|          [  오늘의 운세  ]            |
+--------------------------------------+
```

**"밥" 클릭 시** (포켓몬 메뉴처럼 초원 배경 아래쪽에 짧은 선택지가 겹쳐서 뜸, 설명 문구 없이 라벨만)
```
+--------(초원 배경 아래쪽에 겹침)------+
|   [ 밥 ]     [ 특식 ]  <- 보유 특식 없으면 비활성 |
+--------------------------------------+
```

**"특식" 클릭 시** (보유 특식이 짧은 이름으로 나열되고, 클릭 한 번으로 바로 급여)
```
+--------(초원 배경 아래쪽에 겹침)------+
|  [ 🍖 프로모션 제목 A ]  [ 🍜 프로모션 제목 C ]  |
+--------------------------------------+
```

- 이름/상태 표시(단계 배지는 없음) + 초원 배경 안에 펫 이미지. 일상 대사 말풍선은 펫 이미지 위쪽에서 펫을 따라다님.
- 배경은 픽셀아트 초원(하늘/잔디/꽃 등)이고, 펫은 그 안에서 좌우로 총총 뛰며 돌아다니다가 멈추기도 함. 가끔 눈을 깜빡임.
- 알 단계는 다리가 없어 좌우로 돌아다니지는 않고, 제자리에서 흔들리는 정도의 idle 모션만 가짐.
- 행동 버튼은 목욕/밥/쓰다듬기 3개 노출. "밥"을 누르면 "밥"과 "특식" 중 고르는 짧은 메뉴가 씬 배경 아래쪽에 겹쳐서 뜨고(사용자 확인: 설명 문구 없이 라벨만, 아래로 늘어지는 드롭다운 아님), "특식"을 선택하면 보유 중인 특식이 짧은 이름으로 나열되어 클릭 한 번으로 바로 급여된다(보유 특식이 없으면 "특식" 비활성). UI는 "밥" 하위에 묶여 있지만 실제 API는 `/pet/feed`(기본 주식)와 `/pet/feed-special-food`(특식)로 완전히 분리된 별개 엔드포인트다 - 1-domain-definition.md "특식 주기 버튼" 규칙(행동/효과 분리)은 UI 배치와 무관하게 그대로 지켜진다.
- 오늘의 운세 버튼은 알 단계에서는 비활성 또는 미노출, 새끼/성체 전용.

## 참고
- 관리자 프로모션 등록/수정 화면은 PRD 3.1절에 "별도 관리자 권한 체계 없이 단일 관리자 계정"으로 명시되어 있으나, 유스케이스 다이어그램(4-use-case-diagram.md)의 실행 주체가 사용자 1명으로 한정되어 별도 화면으로 정의되어 있지 않아 본 문서에서는 제외(화면 자체는 `AdminPromotionsPage.jsx`). 다만 로그인 사용자가 관리자 이메일이면 상단 네비게이션(3번)에 "관리자" 링크가 추가로 노출된다(사용자 확인).
- 모든 화면은 단일 반응형 레이아웃 기준이며 데스크톱/모바일용 별도 와이어프레임을 나누지 않음(PRD 5.4절, 오버엔지니어링 금지 원칙).
