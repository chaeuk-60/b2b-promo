# 펫 디자인 가이드

`1-domain-definition.md`의 펫 상태 정의를 기준으로 실제로 그려야 하는 비주얼 목록.

## 그림체 스펙

- **8×8 도트 픽셀아트**
- **레퍼런스**: 슬라임 캐릭터 — 동글동글한 젤리 몸통, 두꺼운 세로 막대 눈, 볼터치, 윗면 하이라이트, 바닥 그림자
- **새끼**: 모닝빵 단면 같은 둥근 젤리 몸통(둥근 윗면 + 평평하고 넓은 아랫면, 공통) + 두꺼운 눈/볼터치/하이라이트/바닥 그림자, 귀만 각도별로 5종 다르게 붙임. 몸통 색상은 귀 색에 맞춰 연한 톤으로 통일
- **성체**: 몸통이 새끼보다 길쭉해짐, 팔다리는 점(1~2도트) 찍는 정도로 단순 표현(공통, 5종 동일). 귀 모양만 다르면 구분됨

## 알 단계 (귀/팔다리 없음, 몸통만)

eggState 6종을 각각 1장씩:

- 평범 / 더러움 / 반질반질 / 무지개 / 반짝이 / 특식 요청

→ **6장**

## 새끼 / 성체 단계

전체 조합(귀 5종 × mood 8종)을 다 그리면 40장이라 비효율적이므로, 베이스와 표정을 분리해서 조합하는 방식을 권장:

- **베이스 몸통**: 모닝빵 단면 몸통(공통) + 귀 각도 5종 → **5장**(새끼용). 성체는 몸통을 좀 더 길쭉하게 늘리고 팔다리 점을 추가한 버전으로 동일하게 5장
- **mood 오버레이**(표정/이펙트, 베이스 위에 합성): 더러움 / 배고픔 / 삐짐 / 평범 / 행복 / 무지개 / 반짝이 / 특식 요청 → **8장**

  > **버그였다가 고쳐짐**: 처음 구현 때는 이 8장을 귀 종류와 무관하게 "재사용"한다고 오해해서, 토끼 팔레트로 그려진 단일 파일 하나를 어떤 동물 베이스 위에도 그대로 얹었다. mood 오버레이가 투명 배경 위에 표정 부분만 그린 게 아니라 몸통 전체를 불투명하게 다시 그린 파일이라, 귀 모양이 다른 동물(예: 소) 베이스 위에 토끼 모양 오버레이가 얹히면서 두 동물이 뒤섞인 것처럼 보이는 실제 화면 버그로 이어졌다(사용자 확인 스크린샷). 지금은 `frontend/public/images/*-mood-*.svg`로 동물(귀 종류)×단계(새끼/성체)별 합성 파일을 스크립트로 미리 생성해 둔다 - "평범" 오버레이를 기준으로 각 mood가 어떤 픽셀을 바꾸는지만 뽑아서(표정/이펙트 diff), 그 diff를 각 동물 자신의 베이스 몸통(귀 모양·윤곽선색·얼굴색 그대로) 위에 적용하는 방식. 성체 다리 교차 애니메이션(`adultWalkFrameUrl`)과도 프레임이 맞아야 해서 다리 프레임별 변형까지 함께 생성한다(`frontend/src/utils/petSprite.js`의 `moodOverlayUrl`).

## 기타

- **묘비**: "자주 오세요..." 말풍선 포함 1장
- **행복 모션**: 정적 그림이 아닌 돌아다니는 애니메이션(걷기 사이클) — 별도 프레임 필요

## 총계

알 6장 + 새끼/성체 베이스 5장 + mood 오버레이 8장 + 묘비 1장 + 행복 모션 프레임 ≈ **20장 안팎**의 손그림 원본으로 시작하되, 실제 화면에 쓰는 파일 수는 동물×단계×mood×다리프레임 조합을 스크립트로 생성한 합성 파일까지 합쳐 그보다 훨씬 많다(위 버그 수정 내용 참고). 손으로 그리는 원본 수는 그대로 20장 안팎을 유지한다.
