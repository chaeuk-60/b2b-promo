# 펫(다마고치) 상태 다이어그램

> 본 문서는 `docs/1-domain-definition.md`(도메인 정의서) 3장(Pet 엔티티), 5장(상태), 6장(비즈니스 규칙)에 정의된 규칙만을 시각화한다. 새로운 규칙이나 수치는 추가하지 않았으며, 정의서 문구를 그대로 인용한 부분은 note로 표시했다.

## 1. 성장 단계(stage) 상태 다이어그램

근거: 도메인 정의서 3장(Pet.stage, activityCount, stageChangedAt, lastActiveAt), 5장 "성장 단계 전이" · "성체 순환" · "사망"

```mermaid
stateDiagram-v2
    [*] --> 알 : 회원가입 시 자동 생성

    알 --> 새끼 : activityCount 누적 2회 이상\n조건 충족 시 50% 확률로 진화\n(실패 시 activityCount 유지, 행동마다 재도전)
    새끼 --> 성체 : 새끼 단계에서 추가 3회\n(알부터 누적 총 5회 이상)\n50% 확률로 진화\n(실패 시 유지, 재도전)

    성체 --> 알 : 성체가 된 지 2주 경과\n새 알 하나를 남기고 사라짐\n선물(할인쿠폰) 100% 지급\nactivityCount 초기화

    알 --> 묘비 : lastActiveAt 기준 7일 이상 미접속
    새끼 --> 묘비 : lastActiveAt 기준 7일 이상 미접속
    성체 --> 묘비 : lastActiveAt 기준 7일 이상 미접속

    묘비 --> 알 : 다음 로그인 시 새 알로 교체\nactivityCount 초기화

    note right of 묘비
        "사망(lastActiveAt 기준 일주일(7일) 이상 미접속)
        → 펫 사망(다른 전이 조건보다 우선 적용),
        stage가 '묘비'로 전환되고
        '자주 오세요...' 메시지 표시"
        (5장 사망)
    end note

    note right of 성체
        사망 조건과 성체 순환(2주) 조건이
        동시에 충족되면 사망이 우선 적용됨
        (5장 성체 순환)
    end note

    note left of 알
        새 알 생성 시(사망 또는 성체 순환)
        이름을 다시 지어야 함(6장)
        귀 모양은 알→새끼 부화 시 랜덤 결정 후 고정(3장/6장)
    end note
```

## 2. 알 상태(eggState) 상태 다이어그램

근거: 도메인 정의서 3장(Pet.eggState), 5.1절, 5장 "알 상태(eggState) 전이"

```mermaid
stateDiagram-v2
    [*] --> 평범 : 알 생성 시 기본값

    평범 --> 더러움 : 밥을 안 줌(방치)
    더러움 --> 반질반질 : 목욕 행동
    평범 --> 반질반질 : 목욕 행동
    반질반질 --> 평범 : 하루 지나면(자정 기준)
    더러움 --> 평범 : 하루 지나면(자정 기준)

    평범 --> 특식요청 : 요청 가능한 후보 프로모션 1개 이상 있을 때만\n랜덤으로 뽑힘(하루 고정)
    더러움 --> 특식요청 : 후보 있을 때만 랜덤으로 뽑힘
    반질반질 --> 특식요청 : 후보 있을 때만 랜덤으로 뽑힘

    특식요청 --> 무지개 : "특식 주기"로\nrequestedPromotionId 대상 특식 급여
    무지개 --> 평범 : 하루 지나면(자정 기준)

    평범 --> 반짝이 : 자발적 특식 급여 시 50% 확률\n(요청 없는데 다른 특식을 줌,\n나머지 50%는 진화 판정 시도)
    반짝이 --> 평범 : 하루 지나면(자정 기준)

    note right of 특식요청
        "특식 요청 대상(requestedPromotionId) 선정":
        신청완료/기간종료 프로모션 제외한 나머지 중
        찜만 하고 미신청인 프로모션이 있으면 70% 확률로 우선 요청
        (나머지 30%는 그 외 후보 중 랜덤), 하루 동안 고정 (5장)
    end note

    note left of 평범
        "특식 요청" 상태가 아닐 때 자발적으로 특식을 주면
        50% 확률로 진화(activityCount +1),
        50% 확률로 "반짝이"로 변화(둘 중 하나는 항상 발생) (6장)
    end note
```

## 3. 기분(mood) 상태 다이어그램

근거: 도메인 정의서 3장(Pet.mood), 5장 "기분(mood) 전이" (새끼/성체 단계 전용)

```mermaid
stateDiagram-v2
    [*] --> 로그인재계산

    state 로그인재계산 <<choice>>
    로그인재계산 --> 고정상태유지 : 오늘 이미 "행복/무지개/반짝이" 중\n하나가 된 적 있음(자정까지 고정)
    로그인재계산 --> 1회차 : 오늘 1번째 로그인
    로그인재계산 --> N회차판정 : 오늘 2번째 이상 로그인

    1회차 --> 균등랜덤 : "무지개/반짝이" 제외한\n나머지 상태 중 균등 랜덤\n("특식 요청"도 포함)

    state N회차판정 <<choice>>
    N회차판정 --> 행복 : 3번째 이상 로그인이면\n별도로 70% 확률로 행복 덮어씀
    N회차판정 --> 재계산70_30 : 행복으로 안 바뀜(또는 2번째 로그인)

    state 재계산70_30 <<choice>>
    재계산70_30 --> 평범 : 70% 확률
    재계산70_30 --> 균등랜덤 : 나머지 30%\n(1회차와 동일하게 균등 랜덤 재추첨)

    평범 --> 더러움 : (행동 미수행 시 자연 상태, 참고용)
    균등랜덤 --> 더러움
    균등랜덤 --> 배고픔
    균등랜덤 --> 삐짐
    균등랜덤 --> 평범2 : 평범
    균등랜덤 --> 특식요청_m : 특식 요청(후보 프로모션 1개 이상 있을 때만 후보에 포함)

    더러움 --> 평범3 : 목욕 → 평범
    배고픔 --> 평범3 : 밥 → 평범
    삐짐 --> 평범3 : 쓰다듬기 → 평범
    특식요청_m --> 무지개_m : "특식 주기"로 requestedPromotionId 대상 급여 → 무지개
    행복 --> [*] : 자정까지 고정, 화면에서 돌아다니는 모션
    무지개_m --> [*] : 자정까지 고정
    고정상태유지 --> [*]

    note right of 로그인재계산
        "'행복'/'무지개'/'반짝이' 고정 규칙": 오늘 하루 동안
        한 번이라도 이 중 하나가 되면 그날 남은 시간 동안은
        로그인별 재계산 로직을 타지 않고 그대로 유지
        (자정이 지나야 초기화) (5장)
    end note

    note right of 특식요청_m
        requestedPromotionId 선정 로직은
        eggState와 동일(찜만 한 프로모션 70% 가중치) (5장)
    end note
```

## 4. 행동별 효과 요약 (도메인 정의서 5.1절)

근거: 도메인 정의서 5.1절 "단계별 행동·상태 정리" 표, 5장/6장 특식 규칙

| 단계 | 목욕 | 밥(기본 주식, 쌀밥) | 특식 주기 | 쓰다듬기 |
|---|---|---|---|---|
| 알 | eggState → 반질반질, activityCount +1 | eggState 더러움 방지(안 주면 방치→더러움), activityCount +1 | 보유 특식 있으면 급여 가능(아래 특식 규칙과 동일), activityCount +1 | activityCount +1 |
| 새끼 / 성체 | mood "더러움"일 때 → 평범, activityCount +1 | mood "배고픔"일 때 → 평범, activityCount +1 (특식 효과 없음) | 보유 특식 목록 중 하나를 골라 급여(아래 특식 규칙과 동일), activityCount +1 | mood "삐짐"일 때 → 평범, activityCount +1 |

```mermaid
flowchart TD
    A[행동 입력] --> B{어떤 행동?}

    B -->|목욕| C{stage}
    C -->|알| C1["eggState → 반질반질\nactivityCount +1"]
    C -->|새끼/성체| C2["mood '더러움'이면 → 평범\nactivityCount +1"]

    B -->|밥 기본 주식| D{stage}
    D -->|알| D1["eggState 더러움 방지\n(안 주면 방치→더러움)\nactivityCount +1"]
    D -->|새끼/성체| D2["mood '배고픔'이면 → 평범\n특식 효과 없음\nactivityCount +1"]

    B -->|특식 주기| E{보유 특식 1개 이상?}
    E -->|아니오| E0[버튼 비활성화]
    E -->|예, 여러 개면 직접 선택| F{"현재 상태(eggState/mood)가\n'특식 요청'이고\n대상=requestedPromotionId?"}
    F -->|예| F1["무지개로 변화\nactivityCount +1"]
    F -->|아니오, 자발적 급여| F2["50% 진화(activityCount+1)\n50% '반짝이'로 변화\n(둘 중 하나는 항상 발생)\nactivityCount +1"]

    B -->|쓰다듬기| G{stage}
    G -->|알| G1[activityCount +1]
    G -->|새끼/성체| G2["mood '삐짐'이면 → 평범\nactivityCount +1"]
```
